## What to build

Implement the Tool trait, ToolRegistry, and the first real tool: Bash (shell execution). Wire tool execution into the ReAct loop so the loop can detect tool calls in the model's response, execute them, and feed results back for the next turn.

The ReAct loop becomes a real think→act→observe cycle: the model thinks (text), may request a tool (tool_call), the loop executes the tool and feeds the result back (observe), and the model continues thinking. This enables the agent to actually do things like list files, run commands, or read files.

## Agent Brief

**Category:** enhancement
**Summary:** Implement the Tool trait, ToolRegistry, and Bash tool. Expand the ReAct loop to a full think→act→observe cycle with tool execution.

**Current behavior:**
The ReAct loop runs a single turn — it sends messages to the provider and outputs the response. Tool calls in the response are parsed but not executed.

**Desired behavior:**
When the model's response contains tool_calls, the loop executes them via ToolRegistry and feeds results back as tool-role messages. The cycle continues until the model produces a final text response (no tool calls). Multiple tool calls in one response execute sequentially (one per turn). Tool errors are fed back as messages for the model to handle.

**Key interfaces:**
- `Tool` trait — `name() -> &str`, `description() -> &str`, `parameters() -> serde_json::Value` (JSON Schema), `async fn execute(&self, args: serde_json::Value) -> Result<String>`
- `ToolRegistry` — `register(Box<dyn Tool>)`, `get(name) -> Option<&dyn Tool>`, `definitions() -> Vec<ToolDef>`, `async fn execute(name, args) -> Result<String>`
- `BashTool` — implements Tool. parameter is `{command: string}`. Returns stdout+stderr combined. No sandboxing in V1.
- Loop turn logic: after provider.chat(), check response for tool_calls. If present, execute each sequentially, inject tool result messages, call provider.chat() again with updated history. Repeat until no tool calls.

**Acceptance criteria:**
- [x] `Tool` trait defined with name, description, parameters, execute
- [x] `ToolRegistry`: register, lookup, generate ToolDef list, execute
- [x] Bash tool: runs a shell command, returns stdout+stderr
- [x] ReAct loop multi-turn: detect tool_calls → execute → inject result → repeat
- [x] Sequential multi-tool execution (one tool result per turn)
- [x] Tool execution errors fed back as tool result messages
- [x] Unit tests with mock Tool verifying loop turn logic
- [x] Integration test: "list files in /tmp" → Bash tool → result in context

**Out of scope:**
- Tool sandboxing/security
- Parallel tool execution (always sequential in V1)
- MCP adapter (V2)
