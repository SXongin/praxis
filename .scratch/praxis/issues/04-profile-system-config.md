## What to build

Introduce the Profile system: a named YAML configuration that selects which skills, tools, model, provider, system prompt, and loop settings are active for a session. Profiles live in `~/.config/praxis/profiles/`. The CLI gains a `--profile` flag to select a profile at session start.

A user defines a profile YAML (e.g., `~/.config/praxis/profiles/coder.yaml`), then runs `cargo run -- --profile coder`. The core module resolves the profile, wires up the correct provider, tool registry, and skill list for the session.

A user creates YAML files in `~/.config/praxis/profiles/`. Each profile specifies: name, provider, model, system_prompt, skills (list of slugs), tools (list of tool names), max_iterations (optional, default 50). Core resolves the profile and wires up the correct provider, tool registry, and skill list. `--profile <name>` selects a profile by its `name` field. Clear errors for missing/malformed profiles.

**Key interfaces:**
- Profile YAML schema shape: `{name: string, provider: string, model: string, system_prompt: string, skills: [string], tools: [string], max_iterations?: number}`
- `Profile` struct — deserialized from YAML with serde_yaml
- Profile resolution: given a profile name and the profiles directory, find and parse the matching `.yaml` file, return `Result<Profile, ProfileError>`
- Core integration: profile selects which Provider constructor to call (by provider name string), which tools to register (by tool name string), which skills to load (by slug). Skills mapping is a stub at this point — actual loading happens in slice 05.
