## What to build

Implement skill loading: parse SKILL.md files (YAML frontmatter + Markdown body) from `~/.config/praxis/skills/<slug>/SKILL.md`, following the agentskills.io spec. Skills listed in the active profile are loaded at startup and their body content is injected into the model's system prompt as context.

A user creates a SKILL.md in `~/.config/praxis/skills/code-reviewer/SKILL.md`, adds `skills: [code-reviewer]` to their profile, and runs the agent. The agent's system prompt now includes the skill's body content, so it follows domain-specific strategies.

## Agent Brief

**Category:** enhancement
**Summary:** Implement SKILL.md parsing (YAML frontmatter + Markdown body), directory scanning, and injection of skill content into the system prompt.

**Current behavior:**
Profile YAML has a `skills` field listing slugs, but no skill loading exists. The system prompt is whatever the profile's `system_prompt` field provides.

**Desired behavior:**
Skills live as `~/.config/praxis/skills/<slug>/SKILL.md` files. Each has YAML frontmatter (between `---` delimiters) with at least a `name` field, followed by a Markdown body. At session startup, the profile's `skills` list is resolved: for each slug, the corresponding SKILL.md is parsed and its body content appended to the system prompt. Skills and tools remain orthogonal — no skill field references a tool.

**Key interfaces:**
- `Skill` struct — `{name: String, description: Option<String>, body: String}`. The frontmatter provides name/description; body is the Markdown content.
- `SkillLoader` — scans `~/.config/praxis/skills/` for subdirectories containing SKILL.md. Parses each, returns `Vec<Skill>`.
- SKILL.md format: `---\nname: skill-name\ndescription: optional\n---\nMarkdown body here...`
- System prompt assembly: base prompt from profile + "\n\n## Skills\n\n" + each skill's body appended (with skill name header). All skills loaded at startup (no progressive disclosure in V1).
