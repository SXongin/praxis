## What to build

Implement session persistence: save the full message history (including tool results) as JSONL to `~/.config/praxis/sessions/`, and resume a session from that stored history. Tool calls are never re-executed on resume — stored tool results are used as-is.

A user starts a conversation, the agent works through several tool interactions, the user exits gracefully or saves explicitly, and later resumes the session with `--session <id>`. The conversation continues exactly where it left off.

- [x] Unit tests for JSONL round-trip with messages containing tool calls and results
- [x] Integration test: run agent, save, resume, verify history continuity

## Agent Brief

**Category:** enhancement
**Summary:** Implement session persistence as JSONL files in `~/.config/praxis/sessions/`, with save-on-exit and resume-by-id support.

**Current behavior:**
Sessions are ephemeral. Exiting the binary loses the entire conversation history.

**Desired behavior:**
The full message history (including tool call and tool result messages) is serialized as JSONL on graceful exit. A session can be resumed by ID, restoring the exact message history. Tool calls are never re-executed on resume — stored tool results are used as-is. `--list-sessions` shows available sessions with IDs and timestamps.

**Key interfaces:**
- Session JSONL format: one JSON object per line. Each line is a serialized `Message` (role + content blocks). First line may be metadata (profile name, timestamp, session id).
- `SessionStore` — `save(id, messages, metadata)`, `load(id) -> (Vec<Message>, metadata)`, `list() -> Vec<SessionSummary>`
- `SessionSummary` — `{id: String, profile: String, created: DateTime, updated: DateTime, message_count: usize}`
- Session storage path: `~/.config/praxis/sessions/<session-id>.jsonl`
- CLI flags: `--session <id>` (resume), `--save` (save on exit), `--list-sessions`, `--new` (start fresh, don't auto-resume)
- On resume: profile is re-resolved from the stored profile name (skills reloaded, tools re-registered), but message history comes from the stored JSONL.

**Acceptance criteria:**
- [x] Session serialization: message history written as JSONL
- [x] Session metadata includes profile name and timestamp
- [x] Save on graceful exit (Ctrl+C or natural loop completion) and on `--save` flag
- [x] Resume: `--session <id>` reads JSONL, restores history, begins new loop iteration
- [x] `--list-sessions` displays saved sessions with IDs and timestamps
- [x] Stored tool results used as-is on resume — tool calls never re-executed
- [x] Unit tests for JSONL round-trip with messages containing tool calls and results
- [x] Integration test: run agent, save, resume, verify history continuity

**Out of scope:**
- Session encryption
- Session export/import formats
- Automatic session saving on crash (only graceful exit)
- Re-executing tool calls on resume
