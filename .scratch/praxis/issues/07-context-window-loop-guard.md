## Agent Brief

**Category:** enhancement
**Summary:** Add token estimation and context window trimming (drop oldest non-system messages), plus a max_iterations loop guard. Both configurable per profile.

**Current behavior:**
Messages accumulate unbounded. No token limits are enforced. The loop runs until the model produces a final response, with no iteration cap.

**Desired behavior:**
Before each provider call, the loop estimates total token usage. If approaching the model's context limit, it drops the oldest non-system messages until under the limit. System messages (containing the skill-injected prompt) are preserved. If the loop exceeds `max_iterations`, it stops with a clear termination message. Both `max_tokens` and `max_iterations` are profile-configurable with sensible defaults.

**Key interfaces:**
- Token estimation function — counts tokens in a Message. Can start with a character-based heuristic (e.g., chars/4 ≈ tokens) and be replaced later with tiktoken. Must be reasonably accurate but doesn't need byte-perfect precision.
- `ContextTrimmer` — given `Vec<Message>` and a `max_tokens: usize`, return a trimmed `Vec<Message>` with oldest non-system messages dropped. Never drops messages with `role == System`.
- Loop iteration counter — increment each turn, check against `max_iterations` from profile (default 50). On exceed: emit "Reached max iterations" assistant message and stop.
- Profile schema gets `max_tokens` field (optional, sensible default per model) and `max_iterations` (optional, default 50).

**Acceptance criteria:**
- [x] Token estimation: implement a reasonable heuristic
- [x] Context window trimming: drop oldest non-system messages when approaching limit, before each provider call
- [x] System messages are never dropped
- [x] max_iterations counter stops loop with clear termination message
- [x] Both limits configurable per profile
- [x] Unit tests: verify message dropping logic for various history compositions
- [x] Unit tests: verify loop terminates at max_iterations

**Out of scope:**
- Summarization of truncated messages (V2)
- Per-message token priority/weighting
- Dynamic token limit detection from provider API
